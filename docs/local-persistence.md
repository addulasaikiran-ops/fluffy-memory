# Local Persistence

## Ownership boundaries

- Room stores app-owned favourites only. A favourite is a reference to a Contacts Provider lookup key or a normalized phone number.
- The app does not mirror contact names, photos, addresses, the address book, or call history into Room.
- Android Contacts Provider and Call Log Provider remain the sources of truth for those records.
- DataStore Preferences stores user-facing preferences: theme mode and haptics enabled.
- Active Telecom call state is transient and is never persisted here.

## Room database

Database: `fluffy-memory.db`

Current schema version: **1** (initial migration baseline).

Entity:
- `favourites`: generated local ID, optional contact lookup key, optional phone number, and sort order.

The repository validates that supplied references are non-blank. Future schema changes must:
1. Increment the Room database version.
2. Add an explicit `Migration(oldVersion, newVersion)` with deterministic SQL.
3. Preserve existing favourite references.
4. Add a migration test from every supported prior schema to the latest schema.
5. Keep exported Room schemas under `app/schemas` (generated by the Room KSP schema export setting).

Do not use destructive migration fallback for user-owned favourites.

## DataStore Preferences

Preference keys:
- `theme_mode`: `SYSTEM`, `LIGHT`, or `DARK`; missing or unknown values resolve to SYSTEM.
- `haptics_enabled`: Boolean; missing value resolves to true.

The repository exposes a Flow and suspend setters. UI state collection and lifecycle handling belong to the presentation layer.

## Tests

JVM tests use Robolectric for the Room in-memory database and temporary DataStore files. They cover favourite insert/read/delete, number-only references, invalid references, the version-1 schema baseline, preference persistence, and defaults.

The CI workflow runs `:app:testDebugUnitTest` only. It does not assemble or upload an APK.
